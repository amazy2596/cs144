## 1 概述 (Overview)

在本周的 Checkpoint 中，你将在现有的 `NetworkInterface` 之上实现一个 **IP 路由器（IP router）**。一个路由器拥有多个网络接口，并可以在其中任何一个接口上接收互联网数据报。路由器的任务是根据**路由表（routing table）**转发它收到的数据报：路由表是一组规则，对于任何给定的数据报，它会告诉路由器：
*   从哪个接口将其发送出去
*   下一跳的 IP 地址

你的任务是实现一个路由器，能够为任何给定的数据报计算出这两件事。（你不需要实现生成路由表的算法，例如 RIP、OSPF、BGP 或 SDN 控制器——只需实现**遵循/执行**路由表的算法。）

你的路由器实现将使用带有全新 `Router` 类的 Minnow 库，并通过测试在模拟网络中检查你的路由器的功能。Checkpoint 6 建立在你在 Checkpoint 5 中实现的 `NetworkInterface` 之上，但不使用你之前实现的 TCP 协议栈。IP 路由器不需要了解任何关于 TCP、ARP 或以太网的信息（仅限 IP）。我们预期你的实现将需要约 **30–60 行代码**。（`scripts/lines-of-code` 工具打印出初始代码中的“Router: 38 lines of code”，而我们的示例解决方案为“89 lines of code”。）

## 3 实现路由器 (Implementing the Router)

在本实验中，你将实现一个 `Router` 类，它可以：
*   追踪路由表（转发规则或路由的列表），并且
*   转发它收到的每个数据报：
    *   发送给正确的下一跳
    *   通过正确的出站 `NetworkInterface` 发送。

你的实现将添加到 `router.hh` 和 `router.cc` 骨架文件中。在开始编写代码之前，请查阅 `router.hh` 中新 `Router` 类的文档。

以下是你要实现的两个方法，以及我们对每个方法的预期：

### 1. `void add_route(uint32_t route_prefix, uint8_t prefix_length, optional<Address> next_hop, size_t interface_num);`

此方法向路由表添加一条路由。你需要在 `Router` 类中添加一个数据结构作为私有成员来存储这些信息。此方法需要做的就是保存该路由以供以后使用。

> **路由的各部分代表什么意思？**
>
> 路由是一条“匹配-动作（match-action）”规则：它告诉路由器，如果数据报要发往某个特定的网络（一个 IP 地址范围），并且该路由被选为最具体的匹配路由，那么路由器应该将数据报转发到某个特定接口上的某个特定下一跳。
>
> *   **“匹配（Match）”**：数据报是发往该网络的吗？`route_prefix` 和 `prefix_length` 共同指定了一个 IP 地址范围（一个网络），该范围可能包含数据报的目的地址。`route_prefix` 是一个 32 位数值 IP 地址。`prefix_length` 是 0 到 32 之间（含）的一个数字；它告诉路由器 `route_prefix` 的多少个**最高有效位（most-significant bits）**是有效的。例如，为了表达发往网络“18.47.0.0/16”（这匹配前两个字节为 18 和 47 的任何 32 位 IP 地址）的路由，`route_prefix` 将是 305070080（$18 \times 2^{24} + 47 \times 2^{16}$），并且 `prefix_length` 将是 16。任何发往“18.47.x.y”的数据报都会匹配。
> *   **“动作（Action）”**：如果路由匹配并被选中，该怎么做。如果路由器**直接连接**到所讨论的网络，`next_hop` 将是一个空的 `optional`。在这种情况下，下一跳就是数据报的目的地址。但如果路由器是通过其他路由器连接到所讨论的网络，`next_hop` 将包含沿途下一台路由器的 IP 地址。`interface_num` 给出了路由器的 `NetworkInterface` 的索引，路由器应使用该接口向下一跳发送数据报。你可以使用 `interface(interface_num)` 方法访问该接口。

---

### 2. `void route();`

这就是见真章的地方。此方法需要将每个传入的数据报路由到下一跳，并从适当的接口发送出去。它需要实现 IP 路由器的**“最长前缀匹配（longest-prefix match）”**逻辑来找到要遵循的最佳路由。这意味着：

*   `Router` 搜索路由表，找到与数据报目的地址匹配的路由。所谓“匹配”，是指目的地址的最高有效 `prefix_length` 位与 `route_prefix` 的最高有效 `prefix_length` 位相同。
*   在匹配的路由中，路由器选择 `prefix_length` 值**最大**的路由。这就是最长前缀匹配路由。
*   如果没有路由匹配，路由器将**丢弃**该数据报。
*   路由器将数据报的 **TTL（生存时间，Time to Live）递减**。如果 TTL 已经为零，或者递减后变为零，路由器应当**丢弃**该数据报。
*   否则，路由器通过适当的接口（即对对应的网络接口调用 `interface(interface_num)->send_datagram()`）将修改后的数据报发送到适当的下一跳。

> 互联网的设计在这里体现出了一种美感（或至少是一种成功的抽象）：路由器永远不需要考虑 TCP、ARP 或是以太网帧。路由器甚至不知道链路层长什么样。路由器只考虑互联网数据报，并且仅通过 `NetworkInterface` 抽象与链路层进行交互。当涉及到诸如“链路层地址如何解析？”、“链路层是否甚至拥有独立于 IP 的自己的寻址方案？”、“链路层帧的格式是什么？”或“数据报载荷的含义是什么？”等问题时，路由器完全不需要关心。

## 5 问题与解答 (Q & A)

*   **我应该使用什么数据结构来记录路由表？**
    取决于你！但请不要搞得太复杂。对于每个数据报，需要消耗 $O(N)$ 的工作量是完全可以接受的，其中 $N$ 是路由表中的表项数量。如果你想做得更高效，我们鼓励你先实现一个可以工作的版本，然后再进行优化，并仔细为你选择实现的内容编写文档和注释。
*   **我该如何将 `Address` 对象形式的 IP 地址转换为可以写入 ARP 消息的原始 32 位整数？**
    使用 `Address::ipv4_numeric()` 方法。
*   **我该如何将原始 32 位整数形式的 IP 地址转换为 `Address` 对象？**
    使用 `Address::from_ipv4_numeric()` 方法。
*   **我该如何比较一个 32 位 IP 地址的最高有效 $N$ 位（其中 $0 \le N \le 32$）与另一个 32 位 IP 地址的最高有效 $N$ 位？**
    这可能是本次作业中“最棘手”的部分——正确处理该逻辑。在 C++ 中编写一个小型的测试程序（一个简短的独立程序）或向 Minnow 添加一个测试以验证你对相关 C++ 运算符的理解并双重检查你的逻辑是值得的。
    请记住，在 C 和 C++ 中，**将 32 位整数移位 32 位会产生未定义行为（undefined behavior）**。测试会在检测此类行为的 Sanitizers（消毒器）下运行你的代码。你可以直接从 minnow 目录运行 `./build/tests/router` 来运行路由器测试。
*   **如果路由器没有到达目的地的路由，或者 TTL 降为零，它难道不应该向数据报的源地址发送 ICMP 错误报文吗？**
    在现实生活中，是的，这会很有帮助。但在此实验中没有必要——直接丢弃该数据报即可。（即使在现实世界中，也不是每个路由器在这种情况下都会向源地址发送 ICMP 消息。）
*   **在这个 PDF 发布后，我可以在哪里阅读更多的常见问题解答（FAQs）？**
    请定期检查网站（https://cs144.github.io/lab_faq.html）和 EdStem。
