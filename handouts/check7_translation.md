## 3 阅读并理解初始代码 (Read and Understand the Starter Code)

作为 Checkpoint 7 初始代码的一部分，我们为你提供了两个使用你的 `ByteStream`、TCP 实现、`NetworkInterface` 和 `Router` 的新“应用程序（apps）”。

*   `apps/tcp_eth_udp.cc`：实现了一个**“完整协议栈（full stack）”的端点**：你的 TCP 实现创建 TCP 段，我们的代码将其封装在互联网数据报（IP）中。然后将这些数据报交给你的 `NetworkInterface`，由其封装在以太网帧中。`tcp_eth_udp` 工具将这些以太网帧封装在用户数据报（UDP）中，并通过普通的互联网发送它们。
*   `apps/fun_router`：通过为你的 `Router` 提供命令行接口来实现一个兼容的 **IP 路由器**。命令行标志可以创建接口，并向路由器的路由表中添加路由。路由器的 `NetworkInterface` 也会发送以太网帧（封装在用户数据报中）通过互联网进行传输。

---

1.  通读这两个工具的源代码，努力理解它们是如何工作的以及它们在做什么。
2.  关键点：**这两个工具都发送 IP-in-Ethernet-in-UDP-in-IP 格式的包**。因此，有两个 IP 地址层在起作用：最外层在真实互联网上发送的互联网数据报所使用的**“物理（physical）”地址**，以及你在本 Checkpoint 中设计的“Checkpoint 7 Capstone 互联网”中使用的**“虚拟（virtual）”地址**。
3.  当你使用这些工具时，“物理”地址将对应于可以到达另一位同学的计算机的真实 IP 地址。这可以包括你先前在 Checkpoint 1 和 3 中使用的 CS144 虚拟专用网络（VPN）；从这些应用程序的角度来看，那也是“真实”的互联网。
4.  相比之下，“虚拟”地址将是你自己的发明——**我们希望你设计一个具有有趣拓扑结构的互联网**，由尽可能多的路由器路由数据包，并配置适当的路由表，以便多名学生可以同时在这个“虚拟”互联网上相互通信。

## 4 在你自己的虚拟机上构建一个微型互联网 (Make a Tiny Internet on Your Own VM)

为了开始，我们将在你的计算机内部重现 1969 年历史性的“第一次 ARPANET 连接”（互联网的前身）——加州大学洛杉矶分校（UCLA）与斯坦福大学（Stanford）之间的连接。你将通过在以下两端之间发送 TCP 段，来构建一个虚拟拓扑结构如下的微型互联网：

*   位于“Stanford”、IP 地址为 `50.9.8.7` 的 TCP 服务器
*   位于“UCLA”、IP 地址为 `80.6.5.4` 的 TCP 客户端
*   通过一个带有两个接口的路由器：一个用于 Stanford 的网络（包含一条指向该网络的、范围为 `50/8` 的路由），另一个用于 UCLA 的网络（`80/8`）。

这些 IP 数据报将被封装在以太网帧内，以太网帧又被封装在用户数据报（UDP）内，而用户数据报又被封装在“物理”IP 数据报内。目前，这些“物理”IP 数据报都将保留在你的计算机内部，其内部 IP 地址为 `127.0.0.1`。

完整的“虚拟”和“物理”地址关系图请见 PDF 手册（可以在 handouts 目录下查阅 `check7.pdf` 的第 3 页）。请花一些时间学习该图并理解它——如果第一眼看上去觉得内容很多，这完全正常。

要在你的虚拟机上使用 `fun_router` 和 `tcp_eth_udp` 应用程序运行此拓扑结构，你需要在虚拟机上打开**四个终端**：

1.  **在第一个终端上**，运行以下命令来监控传输中的数据包：
    `sudo tshark -ni lo -d udp.port==2080,eth 'port 2080'`
    其中 `-d udp.port==2080,eth` 告诉 `tshark` 将用户数据报载荷解释为以太网，其中可能包含 IP 和 TCP。
2.  **在第二个终端上**，运行路由器：
    ```bash
    ./build/apps/fun_router \
      interface:stanford:50.0.0.1:9050:127.0.0.1:2050 \
      interface:ucla:80.0.0.1:9080:127.0.0.1:2080 \
      route:50.0.0.0:8:stanford \
      route:80.0.0.0:8:ucla
    ```
    该命令包含了上图中路由器的所有信息（虚拟的和物理的），包括接口名称。你可以单独运行 `./build/apps/fun_router` 来查看描述参数的帮助信息。
3.  **在第三个终端上**，运行 TCP 服务器（在“Stanford”端）：
    `./build/apps/tcp_eth_udp server 2050 50.0.0.1 50.9.8.7:80`
    （你可以单独运行 `./build/apps/tcp_eth_udp` 来查看帮助信息。）
4.  **在第四个终端上**，运行 TCP 客户端（从“UCLA”端）：
    `./build/apps/tcp_eth_udp client 2080 127.0.0.1:9080 80.0.0.1 80.6.5.4 50.9.8.7:80`

如果一切按预期工作，你的 `tshark` 终端将显示一次 ARP 交换，然后是 TCP 连接的建立。你的“路由器（router）”终端将显示双向的大量数据包。你的 TCP 客户端和服务器终端将显示已建立的连接（如你在 Checkpoint 3 中所见）。

尝试在 UCLA 终端中输入“LO”并按回车。它能到达 Stanford 吗？
